## مدیریت ADR

برای ایجاد یا ویرایش ADRهای جدید، لطفاً با تیم معماری هماهنگ کنید.

### فرآیند ADR

1. **پیشنهاد**: ایجاد ADR با وضعیت "پیشنهادی"
2. **بازبینی**: بحث با تیم و ذی‌نفعان
3. **تصمیم**: به‌روزرسانی وضعیت به "تأیید شده"
4. **پیاده‌سازی**: اعمال تغییر معماری
5. **مستندسازی**: نگهداری ADR به‌روز با نتایج واقعی

### قالب‌بندی فایل‌ها

- **قالب**: MADR (Markdown Architecture Decision Record)
- **زبان**: فارسی
- **جداکننده**: DOT (.)
- **نام‌گذاری**: `ADR-XXXX.{title}.md`

### وضعیت‌های ممکن

- **پیشنهادی**: در حال بررسی
- **تأیید شده**: تصویب و پیاده‌سازی شده
- **منسوخ شده**: دیگر استفاده نمی‌شود
- **تعلیق شده**: توسط تصمیم دیگری جایگزین شده

### ابزارها

- **Markdown**: محتوای ADR
- **Git**: کنترل نسخه و همکاری
- **Confluence**: مستندات نهایی و بازبینی
